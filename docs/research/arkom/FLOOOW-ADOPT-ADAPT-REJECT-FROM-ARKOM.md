# FLOOOW — ADOPT / ADAPT / REJECT from ARKOM

Status: STRATEGIC RESEARCH
Captured: 2026-10-10

## ADOPT

### 1. Process-first AI adoption
Do not start with a model.
Start with an economically meaningful process.

### 2. Baseline before implementation
Measure the current process before automation.

FLOOOW extension:
make baseline evidence canonical/reconciled rather than only manually measured.

### 3. Small pilot before scale
Prove cheaply before expanding.

This aligns directly with FLOOOW:
Capital is earned by evidence.

### 4. Human ownership
Every early operational capability needs a responsible human owner.

FLOOOW extension:
formal authority and accountability contract.

### 5. Outcome-oriented packaging
Customers buy:
- saved time;
- improved throughput;
- increased conversion;
- reduced cost;
- better economic outcome.

Not "LLM tokens".

### 6. Ready-made starting points
A blank agent builder creates friction.
Templates / vertical systems can accelerate time-to-value.

## ADAPT

### 1. Ready AI systems -> Governed Capabilities
Instead of an unrestricted "AI employee", FLOOOW should expose a capability with:
- identity;
- allowed inputs;
- allowed tools/actions;
- evidence requirements;
- policy;
- human authority;
- evaluation;
- rollback/revocation;
- outcome metrics.

### 2. Diagnostic -> Economic Opportunity Diagnostic
ARKOM asks:
which process should AI automate first?

FLOOOW should eventually ask:
which process/opportunity creates the highest risk-adjusted marginal economic value if improved?

### 3. 90-day implementation -> Evidence-gated implementation
Replace fixed calendar progression with gates:

BASELINE
-> PILOT
-> SHADOW
-> ADVERSARIAL
-> PRODUCTION_ELIGIBLE
-> PROMOTION

Time alone cannot advance a capability.

### 4. ROI -> Reconciled incremental economic outcome
Do not rely only on:
hours saved + reported revenue.

Add:
- counterfactual/control where feasible;
- contribution margin;
- implementation cost;
- error cost;
- rework;
- downstream impacts;
- attribution uncertainty.

### 5. AI catalog -> Capability marketplace / registry
Future concept:
approved capabilities can be discovered and reused across the enterprise.

But they must have:
provenance,
version,
security,
benchmark,
authority,
monitoring,
revocation.

## REJECT

### 1. Generic "AI employee" as core architectural primitive
Useful marketing metaphor, dangerous architecture.

People/agents do not all share the same responsibility or authority.

### 2. One-click production without promotion gates
One-click may be valid for sandbox/template installation.
It should not mean unrestricted production authority.

### 3. Self-reported ROI as institutional truth
Customer-reported cases are useful evidence, not canonical causal proof.

### 4. Horizontal catalog as FLOOOW's core moat
Sales/support/HR agent catalogs will commoditize.

FLOOOW should compete higher:
truth + economics + opportunities + governed action + learning.
