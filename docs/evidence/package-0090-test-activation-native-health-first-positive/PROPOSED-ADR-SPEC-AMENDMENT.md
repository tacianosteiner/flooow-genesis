## Proposed SPEC-0090 section25 TEST-only registration supplement

Activation recipe identity:
TEST_ONLY/0090/activation/db-clock-in-transaction/v1.
After independently validating the immutable decision and durably preparing
the trusted administrative audit, BEGIN the isolated ADMIN transaction.
Capture pg_catalog.clock_timestamp() exactly once, as finite timestamptz(6),
and capture the registration transaction identity. effective_from is that
captured instant with zero offset. No historical epoch, arbitrary caller
timestamp, offset, GUC, default or renewed signed window is accepted.

Freeze the captured instant in UTC with six fractional digits and as signed
integer epoch microseconds; both representations must agree without floating
conversion. It is immutable metadata outside the unchanged29-tag policy.
Validate exact version, approved complete bytes/digest, all bounds/nesting,
target deployment/incarnation, approval/change/actor and scope before INSERT.
ACTIVE remains derived by acknowledged committed registration, exact current
policy references and fresh database wall clock >= effective_from; it is never
a state flag written by the loader. No readiness or binding activation follows
automatically.

The trusted deployment administrative audit must implement SPEC25.4's existing
external obligation. Identify its actual trusted store and writer/reader
authority before adoption; neither integration_control_audit nor a repository
JSON file is implicitly that store. Create no Package audit table/helper/API.
The audit must bind approval/change identity, actor, deployment/incarnation,
complete canonical policy/digest/version, effective_from, recipe identity,
affected bindings/reference tuples where applicable, validation outcome,
transaction identity and PREPARED/associated/COMMITTED/ROLLED_BACK/UNKNOWN
outcomes with database timestamps. No secrets belong in that record.

Durably PREPARE before BEGIN, associate the exact transaction, then independently
reconcile acknowledged commit or rollback. If the audit is external, claim no
distributed atomicity without its demonstrated protocol. An uncertain or
missing audit outcome leaves NOT_READY and wrapper use denied even if a policy
row is physically committed. A crash between commit and audit acknowledgment
must reconcile by the frozen transaction/target/version tuple; it cannot
create an eligible deployment from a guessed successful outcome.

Duplicate SQL registration uses plain INSERT and fails. Exact replay only
reconciles the existing immutable approved registration; it never recaptures
activation time, upserts or renews anything. Divergent version/digest/time/
target/approval/scope is denied. Future activation remains non-eligible until
the fresh DB clock reaches it. NULL/nonfinite activation fails. Changed policy
or activation metadata requires a newly approved version under25.5; fixture-1
cannot be rewritten. Historical VECTOR_1 manifest/header/signed windows stay
unchanged; R's historical read semantics must be qualified directly.

## Proposed TEST native-health supplement

Use the seven names and witness definitions verbatim from
NATIVE-HEALTH-DESIGN.json. Trusted bootstrap supplies actual process identity,
pidfd anchor, boot/namespace/container/start, fresh externally recorded slot
generation and enrollment before eligibility. The independent guard observes
the exact current ledger revision, authenticated original BOOTTIME emission,
completed participant-specific functional result, dependency and catalog
identity. HOST_PLATFORM independently anchors/monitors HEALTH_GUARD; failure
to establish that root denies every participant. A heartbeat, alive process,
signature success, JSON flag or self-reported result never substitutes for
the required work witness.

Keep the approved fixture-1 watchdog interval and health values: 100us actual,
200us approved maxima. S04 uses policy_values[23], tag24 actual100us, for its
database watchdog age guard. Do not invent a different per-participant
duration. Independently establish the exact original-emission freshness
mapping and applicable numeric rule before accepting any observation.
The design currently supplies no separately adopted numeric native-participant
window; this supplement may not silently fill that gap.

Absence, wrong binary/host identity, stale or future observation, generation
replacement, missing enrollment, unauthenticated linkage, replay, dependency/
catalog mismatch, cross-participant evidence, observer loss and failed work
deny readiness. Quarantine is monotonic; stale generations cannot invalidate
newer enrollment or restore eligibility. Replacement requires a new anchored
generation and fresh observations; unknown prior lineage requires a new
incarnation. Retain ownership/reconciliation duties on failure.
