## Generations: one necessary ephemeral control epoch

One 32-byte OS-CSPRNG control_epoch labels the joint pair of live postmaster/receiver anchors under current approved deployment/incarnation. Supervisor retains the token-to-anchor association in protected current state outside DB backup; no reuse after loss/restore. Supervisor restart must quiesce and drain existing enrollment before exposure resumes. Independent native bootstrap receives the authenticated current epoch/anchor association through the protected deployment channel; a caller or unverified socket challenge cannot author it. Without that channel validation, admission remains disabled.

Comparison is exact32-byte epoch plus independently live matching process anchors/context; equality of copied token alone is insufficient. Receiver/postmaster death invalidates the entire registry before new ACCEPT. Current epoch must be checked before acceptance, every effect eligibility observation and signaling. Backend pidfd identity remains the actual target; numeric PID/start do not replace it. No PgStartTime-only epoch, persistent nonce table or generation inferred from copied DB state is introduced.

Exact proposed bootstrap transport: trusted supervisor starts receiver and postmaster as controlled children using atomic child pidfd acquisition (Linux clone3 CLONE_PIDFD), not external observe/open/revalidate. ## Canonical wire frames

All packets: magic ASCII `G3F4` (4 bytes), version u16 big-endian=1, type u8, reserved u8=0, payload_length u32 big-endian. Exactly one complete seqpacket, total length exactly12+payload_length, hard maximum1024 bytes. Reject truncation/MSG_TRUNC/MSG_CTRUNC, trailing bytes, unknown version/type/fields, nonzero reserved, extra packets or malformed ancillary data. All required fields nonnull; no TLV extension or optional silent defaults in V1. Length limits are engineering resource bounds proposed here, not time policy changes.

Strings encode u16 byte length then exact UTF-8 NFC bytes, no NUL/invalid UTF-8, length1..63 for PG names; reject rather than truncate or normalize during comparison. OIDs u32 nonzero. Purpose/slot u8 in1..4 using frozen mapping. UUID references are16 raw RFC4122 bytes. Digests32 bytes. Timestamp fields signed-int64 finite microseconds in PostgreSQL epoch basis, rejecting infinity; backend/postmaster timestamp are corroboration, not authority or timer. Integers network big-endian, no padding. Missing data denies.

REQUEST(type1), exact order: binding_id16; slot1; authenticated_role_oid4; role_name length+bytes; database_oid4; database_name length+bytes; deployment_id16; incarnation_id16; control_epoch32; postmaster_start8; backend_start8; binding_fingerprint32; policy_digest32. Maximum REQUEST311 bytes including header. Binding/fingerprint and policy digest are necessary to prevent multiple-header and policy-context substitution; no new policy version string is needed because current approved context resolves the exact digest/version. No serialized PID, fd integer, caller sequence or request nonce. Exactly one self-pidfd via SCM_RIGHTS. Receiver enables SCM_CREDENTIALS and SCM_PIDFD, obtains SO_PEERCRED/SO_PEERPIDFD independently, requires exact ancillary counts/types and closes all unexpected received FDs. Use close-on-exec and nonblocking bounded I/O throughout.

Receiver-derived fields: kernel connected-peer/message-sender/supplied anchor identity and liveness, approved OS UID/GID/namespace and current epoch, canonical header/role/db/policy/readiness, scope/approval current status and registry state. Server-derived request bytes are cross-checked against these independent expectations and catalog process evidence; OS UID alone is never enough. Registry keyed by current context+binding+slot+retained backend object, not numeric PID. Dead/readable pidfd takes priority over signal0 success.

ACCEPT(type2): control_epoch32 + request_digest32. DENY(type3): control_epoch32 + request_digest32 + reason_code u16. Request digest is SHA256 of exact REQUEST packet bytes solely for response association, not signature/authentication. Reason codes:1 MALFORMED;2 UNKNOWN_CONTEXT;3 IDENTITY_MISMATCH;4 HEADER_MISSING_OR_AMBIGUOUS;5 POLICY_OR_APPROVAL_INVALID;6 DEAD_OR_MISMATCHED_ANCHOR;7 GENERATION_STALE;8 DUPLICATE_CONFLICT;9 RECEIVER_UNAVAILABLE;10 DEADLINE;11 ENFORCEMENT_UNQUALIFIED. Malformed packets need not receive a response if safely associating a digest is impossible; close=DENY. No diagnostic secret/free text. A reply is accepted only on the same verified peer/socket and exact request digest/epoch.

REQUEST -> VALIDATE -> provisional registry -> ACCEPT / DENY. Recheck anchors/current context and qualified enforcement immediately before sending ACCEPT. Backend rechecks local anchor, reply identity, epoch and total deadline before returning from handler. Registry can precede ACK; if ACK is lost, backend FATAL/exits and death invalidates the provisional record. Socket closure after successful ACK is not backend death; registry retains the process fd independently. This protocol registers identity only, never sets watchdog_healthy or READY.

An exact approved context may register monitoring identity while its matching readiness remains NOT_READY; enrollment does not require a self-created healthy projection and cannot turn NOT_READY into operation eligibility. Wrapper/preflight/readiness guards independently deny work until their existing conditions hold. Receiver ACCEPT requires an independently armed qualified enforcement path, valid approved scope and current canonical assignment, not a claim that host approval or identity alone authorizes effects. This avoids circular enrollment-to-health self-certification.

## Finite synchronous ACK semantics

Timer begins before any potentially blocking roster/header lookup or socket operation in the handler, uses monotonic elapsed time (Linux CLOCK_BOOTTIME includes suspend), and covers lookup, connect, transfer, receiver validation and full reply. Trusted bootstrap must already be available; no blocking fetch can precede the timer. Positive finite approved ack_deadline_us and maximum are validated at entry with overflow-safe arithmetic. Interrupted operations never reset the deadline; waits use remaining budget. No caller timeout, SQL wall-clock change, retries, second socket, local cache or expiry renewal extends it. Receiver bounds its work under the same approved budget, while backend's elapsed timer is decisive; no cross-process wall-clock subtraction is needed.

Partial frame, FD transfer failure, socket/receiver loss, late/lost ACK, unknown epoch or suspend consuming the budget -> DENY/FATAL, close local/received resources, no governed usable session. Client cancel is not assumed to cancel login processing; native bounded I/O is required.
