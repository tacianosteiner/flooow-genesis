Status: PREPARED_POST_MVP_RESEARCH
Implementation authority: NONE
MVP dependency: NONE

## 1. Purpose

This document prevents post-MVP development from duplicating, renaming or
silently replacing capabilities already present in FLOOOW.

Every future implementation block must begin with ancestry.

Mandatory classifications:

REUSE
- capability already exists and is correct;
- do not duplicate it.

EVOLVE
- a valid foundation exists;
- implement only the real missing delta.

SUPERSEDE
- prior capability exists but new evidence justifies replacement;
- preserve history and provide explicit justification.

NO-OP
- proposed work is already fully covered;
- implement nothing.

CONFLICT
- proposed work contradicts existing authority, semantics or architecture;
- STOP before implementation.

BUILD
- a genuinely new nucleus is required.

COMPOSE
- value comes primarily from governed composition of existing capabilities,
  not from another independent subsystem.

External prior art must be classified separately as:

ADOPT
ADAPT
REJECT

External popularity does not establish architectural authority.
